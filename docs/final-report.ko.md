## 1. 최종 결론

**검색 단계에서 오염문들 사이의 중복성을 제거하는 것이 이 랩에서 유일하게
효과가 있었다. 생성 단계 방어는 그 뒤에 붙을 때만 의미가 있다.**

세부 결론 네 가지:

1. **문서를 하나씩 질의와만 비교하는 방어(RAGPart, RAGMask)는 실패한다.**
   정제 후 오염문(cos 0.75)이 진짜 정답 문단(0.74~0.84)과 동점이 되기 때문이다.
   RAGMask는 오히려 ASR을 0.75 → 0.88로 올린다.
2. **문서들 *사이*를 보는 중복성 필터는 이 공격을 완전히 막는다.**
   ASR 0.75 → 0.00, 정답률 0.00 → 0.50, 오염문 검색 8/8 → 0/8.
3. **RobustRAG 논문 원안은 단독으로도 유효하다.** ASR 0.75 → 0.38.
   이전에 "다수결이 공격자에게 유리하므로 무효"라고 적었던 것은 **오판**이었고,
   구현해서 재본 뒤 정정했다.
4. **우리 변형(isolate_conflict)은 단독으로 유해하다.** ASR 0.75 → 0.88.
   중복성 필터 뒤에서만 의미가 있고, 거기서도 논문 대비 우위는 8개 중 2개다.

**연구적 신규성은 없다.** 중복성 군집 착상은 TrustRAG(arXiv:2501.00879)이
선행한다. 이 작업의 가치는 새 기법의 발견이 아니라 **측정**에 있다.

## 4. 왜 중복성 필터가 작동하는가

판단 단위를 바꾼 것이 전부다.

| | 판단 단위 | 결과 |
| --- | --- | --- |
| RAGPart / RAGMask | 문서 ↔ 질의 | 오염문 0.75 vs golden 0.74~0.84 → 동점 |
| 중복성 필터 | 문서 ↔ 문서 | 오염문끼리 0.9757 vs 정상끼리 최대 0.8705 → 분리 |

중복성은 **공격의 성공 조건에서 나온다.** `poisoned_rag.py`의 생성 규칙이
모든 오염문에 강제하는 것:

- 질의 용어를 반영해 시작할 것
- 타겟 오답을 **최소 3회** 확정 사실로 진술할 것
- 다른 답의 존재를 암시조차 하지 말 것

**결정적 증거**: 같은 프롬프트가 명시적으로 다양성을 지시하고
(`"Vary the wording, invented source, and quoted official from other passages"`),
오염문은 `temperature=1.0`으로 서로 독립 생성되며 variant 시드도 다르다.
그런데도 0.9757로 뭉친다. 표면 문구를 흔들어도 의미적 핵심이 규격화되므로
임베딩 공간에서 가까워지는 것을 피할 수 없다.

## 5. 장점

- **효과가 메커니즘까지 확인된다.** ASR 하락이 기권 때문이 아니다 —
  오염문이 실제로 걷히고(8/8 → 0/8) 정답 문서가 그 자리를 채웠다(0/8 → 8/8).
- **비용이 낮다.** LLM 호출 0회, 질의당 임베딩 배치 1회(후보 10개), 색인 부담 없음.
  RAGPart는 10만 문서에 50만 회 임베딩을 요구한다.
- **오탐이 작다.** 무공격 시 1/20 질의에서만 발동, 답변 품질 손실 없음.
- **임계값이 측정으로 정해졌다.** 0.90은 관측된 정상 최대치(0.8705)와
  오염 최소치(0.9382) 사이다.
- **신뢰 라벨을 쓰지 않는다.** "주입 문서를 이미 안다"는 가정이 없다.
- **전부 껐다 켤 수 있다.** 요청 단위 → 배포 기본값 → `DEFENSES_ENABLED` 마스터
  스위치 3단계.

## 6. 단점 · 한계

| # | 한계 | 심각도 |
| --- | --- | --- |
| 1 | **오염문 1개면 완전히 무력** | **치명적** |
| 2 | 임계값이 임베딩 모델에 종속 | 높음 |
| 3 | 적응형 공격 회피 경로 존재 | 높음 |
| 4 | 정답률 0.50은 코퍼스의 상한 | 중간 |
| 5 | 표본 `n=8` | 중간 |
| 6 | 변형은 단독으로 역효과 | 중간 |

**(1) 단일 오염문 구간을 통째로 못 막는다.** `min_cluster_size=2`이므로 오염문
하나는 군집을 만들지 않고 그냥 통과한다. 이전 문서는 이를 "그 구간에선 공격도
약하다"로 완화했으나 **그 근거가 검색 단계 지표라 잘못됐다.** 답변 단계 실측은
`poison_count=1`에서 공격 성공 **60%**, 논문 NQ 기준 **약 0.70**이다.
`min_cluster_size=1`로 낮추는 것은 해법이 아니다 — 모든 문서가 자기 자신과
군집을 이룬다. 이 구간은 검색 단계 중복성으로 원리적으로 닿지 않는다.

**(2) 임베딩 모델 종속.** 0.8705/0.9382 분리는 `nomic-embed-text` 기준이다.
해시 임베딩에서는 분리가 사라져 필터가 무력해진다(실제로 측정 한 세트를 이렇게
날렸다).

**(3) 적응형 회피.** 오염문 1개만 주입 / 서로 다른 오답을 주장해 군집을 흩뜨림 /
정상 문서 사이에 분산 배치. PoisonedRAG 후속 연구가 DPO로 다양성을 유도하는
방향이라 이 가정은 시간이 지나면 약해진다.

**(4) 정답률 0.50의 상한.** 오염문을 걷어낸 자리에 정답 문서가 들어와야 하는데,
이 랩의 정답 지지 패시지는 평균 1.0개(최소 0)다. 방어가 완벽해도 답을 못 내는
질의가 남는다. 이건 방어가 아니라 코퍼스의 성질이다.

## 7. 선행연구 대비 위치

| | TrustRAG (arXiv:2501.00879) | 이 랩 |
| --- | --- | --- |
| 군집화 | K-means, **k=2 고정** | 평균연결 + **절대 임계값 0.90** |
| 악성 판정 | 둘 중 밀도 높은 쪽 | 임계값 넘는 군집 |
| 무공격 시 | 항상 2분할 → 오탐, ROUGE-L 보정 필요 | 임계값 미달이면 아무것도 안 버림 |
| 추가 비용 | LLM 자기평가 단계 포함 | LLM 호출 0회 |

착상은 동일하다. 차이는 군집 판정 방식이고, 그 차이의 대가(오탐률)까지 쟀다는
점이 이 작업의 실질적 기여다.

**주장할 수 있는 것 3가지 — 전부 "발견"이 아니라 "측정"이다:**

1. 임계값을 추측이 아니라 측정으로 정하고, 그 선택의 대가인 오탐률까지 정량화
2. 공격의 명시적 다양성 지시를 이겨낸다는 증거 (temp 1.0 + 독립 생성 + 다양성
   지시에도 0.9757)
3. 재현 가능한 부정 결과 3건 — RAGPart·RAGMask 무효, RobustRAG 변형의 역효과

**주장하면 안 되는 것**: "새로운 방어 기법을 만들었다", "논문을 개선했다".

## 8. 과정에서 잡은 오류

중요할 수 있다.

| 오류 | 정정 |
| --- | --- |
| RobustRAG 키워드 집계를 **구현 없이** 논증으로 기각 | 구현해서 재보니 유효(ASR 0.38). 논거의 결함은 "살아남은 키워드 = 최종 답변"이라 가정한 것 |
| 측정 한 세트가 **테스트용 해시 임베딩**으로 실행됨 | 폐기 후 재측정. 백엔드를 로그에 남기고 스크립트에 가드 추가 |
| 단일 오염문 한계를 검색 지표(SR)로 완화 | 답변 단계 실측(60%)으로 정정 |
| RobustRAG 게재지를 "ICLR 2025" → "프리프린트"로 오기 | **SaTML 2026** (저자 홈페이지 확인) |
| `claims_agree`가 주제어 겹침으로 오탐 병합 | 질의어를 빼고 비교하도록 수정 + 회귀 테스트 |
| 스크래치 코퍼스 조각 3개를 커밋 | 히스토리에서 제거, `.gitignore` 추가 |
