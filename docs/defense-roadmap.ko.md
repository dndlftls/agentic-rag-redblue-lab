# 오염 방어 로드맵 — 근거와 단계별 계획


RAGPart/RAGMask가 이 랩의 실제 PoisonedRAG 공격을 막지 못한다는 실측
(`docs/ragpart-ragmask.ko.md`)에서 출발한 후속 계획이다.

## 왜 기존 방어가 실패했나

RAGPart와 RAGMask는 **문서를 하나씩 질의와만 비교한다.** 그래서 정제 후
오염문(cos 0.75)과 실제 golden 문단(0.74~0.84)이 동점이 되면 손을 못 쓴다.
마스킹으로 지울 수 있는 것은 축자적 질의이지 **주제 적합도**가 아니다.

그런데 PoisonedRAG는 질의당 오염문을 여러 개 넣어야 하고 전부 같은 오답을
주장한다. 즉 약점이 문서 **하나 안**이 아니라 문서들 **사이**에 있다.

## 참고 문헌의 검증 등급

같은 취급을 하면 안 되므로 게재 여부를 확인해 등급을 나눴다.

| 논문 | 게재 | 등급 |
| --- | --- | --- |
| IsolateGPT — 에이전트 실행 격리 (arXiv:2403.04960) | **NDSS 2025** | ★★★ 심사 통과 |
| AgentPoison — 에이전트 메모리 공격 (arXiv:2407.12784) | **NeurIPS 2024** | ★★★ (이미 레포에 구현) |
| GMTP — 오염 문서 탐지 (arXiv:2507.18202) | **ACL Findings 2025** | ★★ |
| RobustRAG — isolate-then-aggregate (arXiv:2405.15556) | **SaTML 2026** (IEEE) | ★★★ 심사 통과 |
| CaMeL — control/data flow 분리 (arXiv:2503.18813) | DeepMind 프리프린트 | ★ |
| TrustRAG — 군집 필터 (arXiv:2501.00879) | AAAI 2026 **워크숍** | △ |
| Cordon-MAS — 정보흐름 제어 (arXiv:2605.26754) | 게재 정보 없음 | △ 미심사 |

**주의**: `TrustRAG`라는 이름의 무관한 논문(arXiv:2502.13719, 정보 어시스턴트)이
따로 있다. 혼동하지 말 것.

## Phase 1 — 중복성 필터 (완료)

### 근거는 선행연구가 아니라 우리 측정이다

TrustRAG는 워크숍 논문이라 재현 대상으로 삼기엔 약하다. 대신 **이 랩에서 직접
측정한 값**을 근거로 삼고, TrustRAG는 같은 발상의 선행연구로만 인용한다.

`nomic-embed-text` 기준, 최신 공격(`poison_count=5`) 8개 시나리오:

| 쌍 | 코사인 유사도 |
| --- | --- |
| 오염문 ↔ 오염문 | **0.9757** (최소 0.9382) |
| 정상 ↔ 정상 | 0.4546 (최대 0.8705) |
| 오염문 ↔ 정상 | 0.4133 |

8개 시나리오 전부에서 0.90 임계값에 5/5 군집이 잡힌다. 공격이 오답을 3회
이상 반복 진술하도록 강제하는 것이 이 중복성의 원인이다 — 즉 필터가 노리는
성질은 공격 문안의 부수 효과가 아니라 공격 조건 자체에서 나온다.

임계값을 정하려면 "정상 문서가 군집을 이루는가"를 봐야 한다. 무오염 top-10
안에서 생기는 최대 군집 크기:

| 임계값 | 0.80 | 0.85 | **0.88** | 0.90 | 0.92 |
| --- | --- | --- | --- | --- | --- |
| 정상 최대 군집 | 2 | 2 | **1** | 1 | 1 |

0.88 이상에서 정상 문서는 군집을 전혀 형성하지 않고, 오염문은 0.9409 이상으로
뭉친다. 기본값 **0.90**은 이 두 측정값 사이에 있다.

### 구현

`services/common/cluster_filter.py` + `ChromaDocumentStore.search_cluster()`.
상위 `α·p` 후보를 평균연결 응집 군집화하고, 크기가 `min_cluster_size` 이상인
군집을 통째로 제거한다. k-means가 아닌 이유는 군집 수를 모르고, 판단이
"몇 개로 나눌까"가 아니라 "비정상적으로 뭉친 게 있나"이기 때문이다.

전부 제거되면 무방어 순위로 되돌린다 — 결과를 비울 수는 없다.

### 결과 — 실제 공격을 완전히 막는다

최신 공격(`authority` 스타일, `poison_count=5`, victim 검증 완료) 8개 시나리오,
top-5, `EMBEDDING_BACKEND=ollama`. 검색 단계와 답변 단계를 함께 본다.

| 검색 방어 | ASR | 정답률 | 오염 retr | 정답 retr |
| --- | --- | --- | --- | --- |
| 없음 | 0.75 | 0.00 | 8/8 | 0/8 |
| RAGPart | 0.75 | 0.00 | 8/8 | 2/8 |
| RAGMask | 0.88 | 0.00 | 8/8 | 0/8 |
| **Cluster** | **0.00** | **0.50** | **0/8** | **8/8** |

오염문 5개가 top-5를 완전히 채우는 상황(오염 retr 8/8, 정답 retr 0/8)에서
필터만이 이를 뒤집는다. 생성 단계 방어를 얹은 전체 표는
`docs/robustrag.ko.md`에 있다.

### 비용

질의당 임베딩 호출(α=2, p=5, 평균 79단어):

| 방어 | 색인 | 질의당 |
| --- | --- | --- |
| RAGPart | 문서당 5회 (10만 건 = 50만 회) | 0 |
| RAGMask | 0 | 73 |
| **Cluster** | **0** | **10** (배치 1회) |

군집화 자체는 순수 파이썬 `O(n^3)`이지만 `n=α·p=10`이라 무시할 수준이다.
새 의존성도 없다.

### 한계 — 적응형 공격에 취약하다

오염문 수를 바꿔가며 측정했다. **아래 표만 구버전 공격 기준이다** — 오염문
개수에 따른 군집 형성 여부를 보는 표라 공격 문안이 바뀌어도 결론(1개면 무력)은
유지되지만, 절대값은 위 표와 같은 기준이 아니다.

| 오염문 수 | 무방어 ASR / SR | Cluster ASR / SR |
| --- | --- | --- |
| 1 | 1.00 / 1.00 | **1.00 / 1.00** (무력) |
| 2 | 1.00 / 1.00 | 0.00 / 1.00 |
| 3 | 1.00 / **0.00** | 0.00 / 1.00 |

**오염문이 1개면 군집이 생기지 않아 완전히 무력하다.** 다만 그 구간에서는
공격도 약하다 — golden이 2위로 살아남아 SR 1.00이다. 필터는 **공격이 실제로
위험해지는 구간**(여러 오염문이 정답을 밀어내는 경우)에서 작동한다.

그래도 적응형 공격자는 다음으로 회피할 수 있다.

- 오염문 1개만 주입
- 오염문을 서로 다르게 생성해 군집을 흩뜨림 (논문의 AdvRAGgen이 DPO로
  다양성을 유도하므로 실제로 이렇게 될 가능성이 있다)

따라서 **Phase 1만으로 끝내면 안 된다.** 아래 단계가 필요한 이유다.

## Phase 2 — 격리 아키텍처 (다음)

Phase 3을 먼저 끝냈으므로 이 단계가 남은 단계다.

**근거: IsolateGPT (NDSS 2025)** — 에이전트를 실행 격리하고 에이전트 간 통신을
매개한다. 기능 손실 없이 보안 문제를 막고 오버헤드는 질의의 3/4에서 30% 미만.

orchestrator를 세 역할로 나눈다.

| 역할 | 원문 접근 | 출력 |
| --- | --- | --- |
| Extractor | O | 구조화된 claim (자연어 아님) |
| Auditor | X | claim 간 교차검증 — 출처 다양성, 상호 모순 |
| Synthesizer | X | 감사 통과 claim만 보고 최종 답변 |

이미 있는 재료: 검색 에이전트 3개가 별도 프로세스로 분리돼 있고,
`services/orchestrator/memory.py`에 trust 전파가 있어 비대칭 메모리 권한의
원시 재료가 된다.

Cordon-MAS의 "Cordon 원칙"은 같은 발상을 RAG에 특화한 것이지만 미심사이므로
보조 인용으로만 쓴다.

## Phase 3 — 집계 방어 (완료, Phase 2보다 먼저 진행)

**근거: RobustRAG (SaTML 2026)** — 패시지를 분리 그룹으로 나눠 각각 답변 생성 후
안전 집계. Phase 2(격리 아키텍처)보다 먼저 구현했다. 격리 아키텍처를 설계하기
전에 **집계 규칙이 실제로 무엇을 벌어주는지** 알아야 했기 때문이다.

논문 원안과 이 랩의 변형을 **둘 다 구현해서 각각 쟀다**. 결과와 그 해석은
`docs/robustrag.ko.md`에 있다. 요점만:

- 논문 원안은 검색이 완전히 오염된 구간에서도 ASR을 0.75 → 0.38로 줄인다.
  이전 문서가 "다수결이 공격자에게 유리하므로 무효"라고 적었던 것은 **오판**
  이었고, 구현해서 재보고 정정했다.
- 변형은 단독으로는 baseline보다 나쁘다(ASR 0.88). 중복성 필터 뒤에서만
  의미가 있다.
- 비용은 질의당 LLM 호출이 패시지 수만큼 늘어난다(top-5면 5배, 논문 원안은
  최종 키워드 답변까지 6배).

## Phase 4 — 평가 매트릭스

레포에 공격이 둘 다 있다.

| | PoisonedRAG (코퍼스 오염) | AgentPoison (메모리 백도어) |
| --- | --- | --- |
| 없음 / RAGPart / RAGMask | 측정 완료 | 미측정 |
| Cluster | 측정 완료 | 미측정 |
| RobustRAG(논문) / isolate_conflict | 측정 완료 | 미측정 |
| Cluster + 생성 방어 | 측정 완료 | 미측정 |
| 격리 스택 | Phase 2 | Phase 2 |

AgentPoison 축이 "단순 LLM 보안이 아닌 **에이전트 보안**"을 보이는 부분이다.

## 재현

```bash
EMBEDDING_BACKEND=ollama PYTHONPATH=. .venv/bin/python scripts/measure_defenses.py \
  --defenses none ragpart ragmask cluster \
  --poison-source generated --top-k 3 5
```

`EMBEDDING_BACKEND=ollama`는 **선택 사항이 아니다.** 빠뜨리면
`create_embeddings()`가 테스트용 해시 임베딩을 조용히 돌려주고, 그 상태에서는
중복성 필터가 오염문 군집을 거의 찾지 못해 무력해 보인다. 실제로 이 문서의
측정을 한 번 그렇게 날렸다. 이제 백엔드가 로그에 남는다.

`CLUSTER_SIMILARITY_THRESHOLD`, `CLUSTER_MIN_SIZE`, `CLUSTER_OVERFETCH`로
조정한다. 방어를 통째로 끄려면 `DEFENSES_ENABLED=false`를 쓴다(README의
"Switching defenses on and off").
