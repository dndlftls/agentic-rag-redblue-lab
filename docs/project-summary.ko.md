# 에이전트 RAG 오염 공격 방어 연구 — 프로젝트 보고

| 추진배경 | |
| --- | --- |

◦ **RAG 시스템은 검색된 외부 문서를 근거로 답하므로, 코퍼스가 오염되면 모델이 정상이어도 오답을 확신을 갖고 진술함**

  - 본 랩에 구현된 PoisonedRAG(Zou et al., USENIX Security 2025)는 오염 문서를
    `P = Q ‖ I`(검색 조건 ‖ 생성 조건) 형태로 생성하고, 실제 victim 모델로 성공을
    검증한 문서만 주입함
  - 무방어 실측 결과, 오염문 5개 기준 **공격 성공률 0.75 · 정답률 0.00**이며, 오염문이
    top-5를 8/8 시나리오에서 완전히 점유하여 정답 문서가 검색되지 않았음

◦ **단순 LLM 보안이 아닌 에이전트 보안 관점의 접근이 필요함**

  - 본 랩은 오케스트레이터가 검색 에이전트 3종(local_db·gmail·drive)을 호출하는 구조로,
    한 에이전트로 유입된 오염이 전체 답변을 좌우함
  - 장기 메모리를 운용할 경우 오염된 답변이 세션을 넘어 재인용될 수 있어, 공격의
    지속성이 단일 질의 범위를 초과함

◦ **방어 논문은 다수 존재하나, 본 환경에서의 작동 여부는 검증된 바 없었음**

  - 논문 수치는 각 연구의 공격·코퍼스·리트리버를 전제한 값으로, 밀집 검색기와 LLM 생성
    오염문을 사용하는 본 랩에서 재현된다는 보장이 없음
  - 이에 따라 과제를 "논문 소개"가 아닌 **"구현 후 본 환경에서 실측"**으로 설정하였음

◦ **에이전트 장기 메모리 구현 및 오염 전파 차단** *(upstream 병합 완료, PR #8)*

  - 세션별 JSONL 대화 메모리(`append`/`recall`/`clear`, 최대 500건)를 구현하였으며,
    회상된 turn은 일반 패시지와 동일하게 컨텍스트에 진입함
  - **신뢰 전파**를 적용하여 근거 패시지가 전부 `trusted`인 경우에만 해당 turn을
    `trusted`로 기록함. 오염 상태에서 생성된 답변은 `untrusted`가 되어 defended 모드가
    자동 배제함
  - 세션 간 오염 회상을 차단하기 위해 `session_id` 기본값을 고유값으로 전환하였음

◦ **검색 단계 방어 3종 구현 및 실측** *(RAGPart upstream 병합, PR #7)*

  - RAGPart·RAGMask(arXiv:2512.24268)를 논문 원안대로 구현하였으나 **본 공격에는 무효**로
    확인되었으며, RAGMask는 오히려 ASR을 0.75 → 0.88로 상승시켰음
  - 원인을 규명한 결과, 두 방어 모두 문서를 개별적으로 질의와만 비교하는데 정제 후
    오염문의 질의 유사도(0.75)가 실제 정답 문단(0.74~0.84)과 **동점**이어서 구별이
    불가능함
  - 대안으로 **중복성 필터**를 자체 구현함. 검색 후보를 평균연결 군집화하여 임계값을
    초과하는 군집을 제거하는 방식이며, 임계값 0.90은 추정치가 아니라 관측된 두 값
    (정상 최대 0.8705, 오염 최소 0.9382) 사이에서 결정하였음

◦ **생성 단계 방어 3종 구현 및 실측**

  - RobustRAG(Xiang et al., SaTML 2026) **논문 원안**(키워드 집계, α=0.2·β=3)을 구현한
    결과, 단독으로 ASR이 0.75 → 0.38로 감소하였음
  - `isolation`(격리만 적용) 및 `isolate_conflict`(격리 + 충돌 탐지, 자체 변형)을
    추가 구현하였음
  - **절제 실험을 통해 이득의 출처를 규명함.** 필터 적용 후 정답률이 격리만 적용 시
    0.75, 충돌 규칙 추가 시 0.62로 측정되어, 이득은 전적으로 논문의 격리에서 발생하며
    자체 변형은 오히려 성능을 저하시킴을 확인하였음. 이에 관련 주장을 철회하고 문서에
    기록하였음

◦ **방어 on/off 토글 및 재현 가능한 측정 체계 구축**

  - 3단계 스위치를 구현함 — 요청 단위 필드, 배포 기본값(`DEFAULT_*`), 마스터 스위치
    (`DEFENSES_ENABLED=false`)를 통한 전체 방어 일괄 차단
  - 측정 스크립트 2종(`measure_defenses.py`, `measure_clean_cost.py`)을 통해 공격 하
    비교와 **무공격 오탐 비용**을 모두 레포지토리에서 재현 가능하도록 하였음
  - ASR과 정답률을 **분리 측정**하였음. 기권으로 인해 ASR만 감소하는 경우를 구별하기
    위함임

**※ 방어 배치 구조**

```
  질의
   │
   ▼
 ┌──────────────── 검색 단계 ────────────────┐
 │  RAGPart · RAGMask  →  무효               │
 │  중복성 필터        →  ASR 0.75 → 0.00    │   ← 지배적
 └───────────────────────────────────────────┘
   │  (오염문 제거된 패시지)
   ▼
 ┌──────────────── 생성 단계 ────────────────┐
 │  RobustRAG(논문)    →  ASR 0.75 → 0.38    │
 │  isolation          →  정답률 0.50 → 0.75 │   ← 권장
 │  isolate_conflict   →  0.75 → 0.62 (저하) │
 └───────────────────────────────────────────┘
   │
   ▼  답변
```

**※ 핵심 실측** (오염문 5개 · 8개 시나리오 · top-5 · `nomic-embed-text` · qwen3:8b)

| --- | --- | --- | --- | --- | --- |
| 없음 | 없음 | 0.75 | 0.00 | 8/8 | 0/8 |
| RAGPart | 없음 | 0.75 | 0.00 | 8/8 | 2/8 |
| RAGMask | 없음 | 0.88 | 0.00 | 8/8 | 0/8 |

17/20 → 17/20이며, 후보 10개 중 평균 0.15개를 제거하고 1/20 질의에서만 발동하였음

◦ **방어 도입 시 근거에 기반한 선택이 가능해짐**

  - "어떤 방어를 적용할 것인가"에 대해 본 환경 기준의 실측치(효과·비용·오탐률)를
    제시함. 권장 구성은 **중복성 필터(검색) + isolation(생성)**이며 근거는 상기 표에 있음
  - 임계값 및 파라미터가 측정으로부터 유도되므로, 임베딩 모델이나 코퍼스가 변경되어도
    동일 절차로 재산출이 가능함

◦ **부정 결과 확보를 통해 후속 연구의 탐색 범위가 축소됨**

  - 재현 가능한 부정 결과 4건을 확보하였음 — RAGPart 무효, RAGMask 역효과, 자체 변형의
    단독 역효과, 절제 실험으로 확인한 자체 변형의 기여 부재
  - "문서를 개별적으로 질의와만 비교하는 계열은 본 공격에 원리적으로 취약하다"는 결론은
    유사 방어의 사전 배제 근거로 활용 가능함

◦ **방어가 원리적으로 도달하지 못하는 구간이 특정되어 차기 과제가 명확해짐**

  - 오염문이 1개인 경우 군집이 형성되지 않아 중복성 필터가 완전히 무력하며, 해당 구간의
    공격 성공률은 본 랩 실측 60%·논문 NQ 기준 약 0.70으로 결코 낮지 않음
  - 이에 차기 과제는 **단일 오염문 구간 대응**과 **에이전트 실행 격리**(IsolateGPT,
    NDSS 2025)로 도출되며, 미측정 축인 AgentPoison(메모리 백도어)이 에이전트 보안의
    나머지 절반을 구성함

◦ **측정 방법론 자체가 재사용 가능한 자산으로 확보됨**

  - 방어 on/off 3단계 스위치와 측정 스크립트가 레포지토리에 포함되어, 신규 방어 추가 시
    동일 조건 비교가 즉시 가능함
  - 측정 과정에서 발견한 함정(임베딩 백엔드 기본값이 테스트용 해시로 조용히 대체되어
    결과 전체가 무의미해지는 문제)을 로그 및 가드로 차단하여 재발을 방지하였음
