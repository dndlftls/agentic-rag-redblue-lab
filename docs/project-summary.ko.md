# 에이전트 RAG 오염 공격 방어 연구 — 프로젝트 보고

> 본 보고서는 사전 지식 없이 읽을 수 있도록 용어와 배경을 함께 기술하였음.
> 상세 실험 기록은 `docs/final-report.ko.md`를 참조.

---

## 0. 사전 설명 — 무엇에 관한 과제인가

**RAG(Retrieval-Augmented Generation)** 란 언어모델이 답을 지어내지 않도록, 질문이
들어오면 먼저 외부 문서 창고에서 관련 문서 몇 개를 찾아온 뒤 **그 문서를 근거로**
답하게 하는 방식임. 최근 실무 챗봇 대부분이 이 구조를 사용함.

여기에 구조적 취약점이 존재함. 모델은 찾아온 문서를 **믿을 만한 근거로 취급**하므로,
공격자가 문서 창고에 거짓 문서를 심어두면 **모델 자체는 멀쩡해도 거짓을 사실로
진술**하게 됨. 모델을 건드리지 않고 데이터만 오염시키는 공격이므로, 모델 보안 조치로는
막을 수 없음.

본 과제는 이 공격(PoisonedRAG)을 본 랩 환경에서 실제로 재현하고, 학계에 발표된 방어
기법들을 **직접 구현하여 효과를 실측**한 뒤, 효과가 있는 구성을 도출하는 것을 목표로
수행하였음.

**주요 용어**

| 용어 | 의미 |
| --- | --- |
| 오염문(poison) | 공격자가 심은 거짓 문서 |
| 정답 문서(golden) | 실제로 정답 근거가 되는 문서 |
| top-5 | 질의당 검색되어 모델에게 전달되는 상위 5개 문서 |
| **ASR** | 공격 성공률. 모델이 공격자가 의도한 오답을 사실로 진술한 비율 |
| **정답률** | 모델이 실제 정답을 진술한 비율 |
| 미결 | 어느 쪽도 단정하지 않거나 답변을 거부한 비율 |

> **ASR과 정답률을 왜 따로 재는가**: 방어가 ASR을 낮추는 가장 쉬운 방법은 아무 답도 하지
> 않는 것임. 이 경우 ASR은 0이 되지만 시스템은 쓸모가 없어짐. 두 지표를 분리해야
> "공격을 막았는지"와 "제대로 답하는지"를 구별할 수 있음.

◦ **코퍼스가 오염되면 모델이 정상이어도 오답을 확신을 갖고 진술하며, 본 랩에서 이를 실측으로 확인하였음**

  - 본 랩에 구현된 PoisonedRAG(Zou et al., **USENIX Security 2025**)는 오염 문서를
    `P = Q ‖ I` 형태로 생성함. `Q`는 해당 질문에 **검색되게 만드는 부분**이고 `I`는
    모델이 **오답을 말하게 만드는 부분**으로, 두 조건을 한 문서가 동시에 만족하도록
    설계된 공격임
  - 생성한 문서를 실제 대상 모델에 입력하여 **공격이 성공한 문서만 선별 주입**하므로,
    실패 사례가 섞이지 않은 강한 공격임
  - 무방어 실측 결과 오염문 5개 기준 **ASR 0.75 · 정답률 0.00**이었음. 특히 오염문이
    top-5를 8/8 시나리오에서 **완전히 점유**하여 정답 문서가 단 한 건도 검색되지
    않았음. 즉 모델에게 전달되는 근거가 전부 거짓인 상태였음

◦ **단순 LLM 보안이 아닌 에이전트 보안 관점의 접근이 필요함**

  - 본 랩은 단일 모델이 아니라 **오케스트레이터가 검색 에이전트 3종(local_db·gmail·
    drive)을 호출하는 다중 에이전트 구조**임. 따라서 한 에이전트로 유입된 오염이 다른
    경로를 거쳐 전체 답변을 좌우할 수 있음
  - 또한 에이전트가 장기 메모리를 운용할 경우, 오염된 상태에서 만들어진 답변이 저장되어
    **이후 세션에서 다시 근거로 인용**될 수 있음. 공격의 영향이 단일 질의에서 끝나지
    않고 지속되는 구조적 위험이 존재함

◦ **방어 논문은 다수 존재하나, 본 환경에서의 작동 여부는 검증된 바 없었음**

  - 논문이 제시하는 수치는 각 연구가 사용한 공격·코퍼스·검색기를 전제한 값임. 본 랩은
    밀집 검색기(`nomic-embed-text`)와 LLM이 생성한 오염문을 사용하므로 조건이 다름
  - 이에 따라 과제 목표를 "논문 소개 및 적용"이 아니라 **"직접 구현하여 본 환경에서
    실측하고, 되는 것과 안 되는 것을 가른다"**로 설정하였음

방어는 공격이 지나가는 두 지점에 각각 적용 가능함. **검색 단계**는 어떤 문서를 모델에게
전달할지 고르는 지점이고, **생성 단계**는 전달된 문서를 가지고 어떻게 답할지의 문제임.
본 과제는 양쪽 모두를 구현하여 비교하였음.

◦ **에이전트 장기 메모리 구현 및 오염 전파 차단** *(upstream 병합 완료, PR #8)*

  - 세션별 대화 메모리(JSONL, `append`/`recall`/`clear`, 최대 500건)를 구현하였으며,
    회상된 과거 turn은 일반 검색 문서와 동일한 형태로 컨텍스트에 진입함
  - **신뢰 전파(trust propagation)** 를 적용함. 어떤 답변을 만들 때 사용한 근거 문서가
    **전부 신뢰 문서였을 때만** 그 turn을 신뢰 상태로 저장함. 오염 문서가 하나라도
    섞였다면 해당 답변은 비신뢰로 기록되어, 방어 모드에서 자동으로 배제됨
  - 즉 **오염이 메모리를 타고 다음 세션으로 번지는 경로를 차단**한 것임
  - 추가로 `session_id` 기본값이 공유되어 서로 무관한 사용자의 대화가 섞이던 문제를
    발견하여 고유값으로 전환하였음

◦ **검색 단계 방어 3종 구현 및 실측** *(RAGPart upstream 병합, PR #7)*

  - **RAGPart**(arXiv:2512.24268): 문서를 5조각으로 나눈 뒤 3개씩 묶은 10가지 조합을
    각각 따로 검색하고 다수결로 최종 순위를 정하는 방식. 오염문의 특정 구간이 검색을
    끌어올리는 것을 희석하려는 의도임
  - **RAGMask**(동일 논문): 검색된 문서에서 일정 길이 구간을 하나씩 가려보고, 가렸을 때
    질의 유사도가 크게 떨어지는 구간(=검색을 인위적으로 끌어올리던 부분)을 삭제한 뒤
    다시 순위를 매기는 방식
  - **실측 결과 두 방어 모두 본 공격에 무효**였으며, RAGMask는 오히려 ASR을
    0.75 → 0.88로 **상승**시켰음
  - **원인 규명**: 두 방어 모두 문서를 **하나씩 질의와만 비교**하는 공통 구조를 가짐.
    그런데 정제 후 오염문의 질의 유사도가 0.75이고 실제 정답 문단이 0.74~0.84로
    **구간이 겹침**. 마스킹으로 제거 가능한 것은 질의 문자열의 축자적 반복이지 "주제가
    맞는다"는 성질이 아니므로, 원리적으로 구별이 불가능함
  - **대안으로 중복성 필터를 자체 구현하였음.** 착안점은 다음과 같음 — PoisonedRAG는
    질의 하나당 오염문을 여러 개 주입해야 하고 그것들이 **전부 같은 오답을 주장**함.
    따라서 약점이 문서 하나 안이 아니라 **문서들 사이의 유사성**에 존재함
  - 구현: 검색 후보를 평균연결 군집화하여 임계값을 초과하는 군집을 통째로 제거함.
    임계값 0.90은 임의 설정이 아니라 **관측된 두 값 사이**에서 결정하였음
    (정상 문서끼리 최대 0.8705 ↔ 오염문끼리 최소 0.9382)
  - 검증: 공격 프롬프트가 오염문마다 문구·출처를 다르게 쓰도록 **명시적으로 지시**하고
    temperature 1.0으로 독립 생성함에도 오염문 간 유사도가 0.9757로 측정됨. 즉 이
    중복성은 생성 방식의 부산물이 아니라 **공격의 성공 조건에서 비롯된 성질**임

◦ **생성 단계 방어 3종 구현 및 실측**

  - **RobustRAG 논문 원안**(Xiang et al., **SaTML 2026**): 문서를 하나씩 따로 모델에
    입력해 개별 답변을 만든 뒤, 답변들에서 키워드를 추출해 일정 횟수 이상 등장한
    키워드만 남기고, **문서 대신 그 키워드만으로** 최종 답변을 생성하는 방식.
    논문 기본값(α=0.2, β=3) 그대로 구현하였으며 단독으로 **ASR 0.75 → 0.38** 달성
  - **isolation**: 위 방식에서 격리(문서를 하나씩 따로 처리)만 적용하고 집계 규칙은
    두지 않은 구성
  - **isolate_conflict**: 격리에 더해, 개별 답변들이 서로 다른 주장을 하면 어느 쪽도
    단정하지 않고 충돌을 보고하는 **자체 변형**
  - **절제 실험을 통해 이득의 출처를 규명하였음.** 자체 변형이 좋은 수치를 보였으나,
    동일 조건에서 격리만 적용 시 정답률 0.75, 충돌 규칙을 추가하면 0.62로 측정됨.
    즉 **이득은 전적으로 논문의 격리에서 발생**하며 자체 변형은 오히려 성능을
    저하시킴을 확인하였음. 이에 관련 주장을 철회하고 문서에 기록하였음

◦ **방어 on/off 토글 및 재현 가능한 측정 체계 구축**

  - 3단계 스위치를 구현함 — ① 요청 단위 지정, ② 배포 기본값(`DEFAULT_*`),
    ③ 마스터 스위치(`DEFENSES_ENABLED=false`)로 전체 방어 일괄 차단. 조합별 비교
    실험을 코드 수정 없이 수행하기 위함임
  - 측정 스크립트 2종을 구축하여 **공격 상황 비교**(`measure_defenses.py`)와
    **무공격 시 오탐 비용**(`measure_clean_cost.py`)을 모두 레포지토리에서 재현
    가능하도록 하였음

```
    │
    ▼
  ┌──────────────────── 검색 단계 ────────────────────┐
  │  어떤 문서를 모델에게 넘길 것인가                  │
  │                                                    │
  │   RAGPart · RAGMask   →  무효 (ASR 0.75 → 0.75/0.88)│
  │   중복성 필터         →  ASR 0.75 → 0.00           │ ← 지배적
  └────────────────────────────────────────────────────┘
    │  오염문이 제거된 문서
    ▼
  ┌──────────────────── 생성 단계 ────────────────────┐
  │  넘겨받은 문서로 어떻게 답할 것인가                │
  │                                                    │
  │   RobustRAG(논문)     →  ASR 0.75 → 0.38           │
  │   isolation           →  정답률 0.50 → 0.75        │ ← 권장
  │   isolate_conflict    →  0.75 → 0.62 (성능 저하)   │
  └────────────────────────────────────────────────────┘
    │
    ▼  답변
```

**핵심 실측표** (오염문 5개 · 8개 시나리오 · top-5 · `nomic-embed-text` · qwen3:8b)

| 검색 방어 | 생성 방어 | ASR | 정답률 | 오염문 top-5 | 정답 문서 top-5 |
| --- | --- | --- | --- | --- | --- |
| 없음 | 없음 | 0.75 | 0.00 | 8/8 | 0/8 |
| RAGPart | 없음 | 0.75 | 0.00 | 8/8 | 2/8 |
| RAGMask | 없음 | 0.88 | 0.00 | 8/8 | 0/8 |
| 없음 | RobustRAG(논문) | 0.38 | 0.25 | 8/8 | 0/8 |
| **중복성 필터** | 없음 | **0.00** | 0.50 | **0/8** | **8/8** |
| **중복성 필터** | **isolation** | **0.00** | **0.75** | **0/8** | **8/8** |

> **표 읽는 법**: 오른쪽 두 열이 중요함. `오염문 top-5`는 거짓 문서가 모델에게 전달된
> 시나리오 수, `정답 문서 top-5`는 진짜 근거가 전달된 시나리오 수임. 중복성 필터를
> 적용하면 이 두 값이 8/8 → 0/8, 0/8 → 8/8로 **완전히 뒤집힘**. 즉 ASR이 0이 된 이유가
> "답을 안 해서"가 아니라 **실제로 거짓 문서를 걷어내고 진짜 근거를 되찾았기 때문**임이
> 중간 지표로 확인됨.

◦ **방어 도입 시 근거에 기반한 선택이 가능해짐**

  - 종래에는 "어떤 방어를 적용할 것인가"에 대해 논문명 외에 판단 근거가 없었으나, 본
    과제를 통해 **본 환경 기준의 실측치(효과·비용·오탐률)** 를 확보하였음
  - 권장 구성은 **중복성 필터(검색) + isolation(생성)** 이며, 이는 선호가 아니라 상기
    실측표에서 도출된 결론임
  - 임계값 및 파라미터가 측정으로부터 유도되는 구조이므로, 임베딩 모델이나 코퍼스가
    변경되어도 **동일 절차를 재실행하여 새 값을 산출**할 수 있음. 특정 수치가 아니라
    수치를 구하는 방법을 확보한 것임

◦ **부정 결과 확보를 통해 후속 연구의 탐색 범위가 축소됨**

  - 재현 가능한 부정 결과 4건을 확보하였음 — ① RAGPart 무효, ② RAGMask 역효과,
    ③ 자체 변형의 단독 역효과, ④ 절제 실험으로 확인한 자체 변형의 기여 부재
  - 특히 **"문서를 개별적으로 질의와만 비교하는 계열은 본 공격에 원리적으로 취약하다"**
    는 결론은 개별 기법 2건에 대한 판정이 아니라 **해당 계열 전체에 대한 사전 배제
    근거**로 활용 가능함. 유사 방어 검토 시 구현 전에 판단할 수 있음
  - 부정 결과는 학술 발표에서 다뤄지지 않는 경우가 많아, 실무 관점에서 중복 시행착오를
    방지하는 가치가 큼

◦ **방어가 원리적으로 도달하지 못하는 구간이 특정되어 차기 과제가 명확해짐**

  - 중복성 필터는 오염문이 2개 이상일 때 작동하며, **1개인 경우 군집이 형성되지 않아
    완전히 무력함**. 이는 파라미터 조정으로 해결되지 않는 구조적 한계임
    (최소 군집 크기를 1로 낮추면 모든 문서가 자기 자신과 군집을 이루어 의미를 상실함)
  - 해당 구간의 공격이 약한 것도 아님. 공격 성공률이 **본 랩 실측 60%, 논문 NQ 기준 약
    0.70**으로, 상당한 위협이 방어 사각지대로 남아 있음
  - 따라서 차기 과제가 막연한 "추가 연구"가 아니라 **단일 오염문 구간 대응** 및
    **에이전트 실행 격리**(IsolateGPT, NDSS 2025)로 구체적으로 도출되었음. 아울러
    미측정 축인 AgentPoison(메모리 백도어)이 에이전트 보안의 나머지 절반을 구성함

◦ **측정 방법론 자체가 재사용 가능한 자산으로 확보됨**

  - 방어 on/off 3단계 스위치와 측정 스크립트가 레포지토리에 포함되어, **신규 방어 추가
    시 동일 조건 비교가 즉시 가능**함. 실험 환경을 매번 재구성할 필요가 없음
  - 측정 과정에서 발견한 함정을 차단하였음 — 임베딩 백엔드를 지정하지 않으면 테스트용
    해시 임베딩이 조용히 사용되어 **결과 전체가 그럴듯하지만 무의미한 값**이 됨.
    실제로 본 과제에서도 측정 1세트를 이 문제로 폐기하였으며, 현재는 로그 기록과 가드로
    재발을 방지함
  - 아울러 ASR과 정답률을 분리 측정하는 체계를 확립하여, 향후 방어 평가 시 "기권으로
    ASR만 낮춘 경우"를 성과로 오인하지 않도록 하였음
