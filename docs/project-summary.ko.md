# 에이전트 RAG 오염 공격 방어 연구 — 프로젝트 보고

| 추진배경 | |
| --- | --- |

◦ **RAG 시스템은 검색된 외부 문서를 근거로 답하므로, 코퍼스가 오염되면 모델이 정상이어도 오답을 확신을 갖고 말한다**

  - 이 랩에 구현된 PoisonedRAG(Zou et al., USENIX Security 2025)는 오염 문서를
    `P = Q ‖ I`(검색 조건 ‖ 생성 조건)로 만들고, 실제 victim 모델로 성공을 검증한
    문서만 주입한다
  - 무방어 실측: 오염문 5개 기준 **공격 성공률 0.75 / 정답률 0.00**, 오염문이 top-5를
    8/8 시나리오에서 완전히 점유해 정답 문서가 아예 검색되지 않는다

◦ **단순 LLM 보안이 아니라 에이전트 보안 관점이 필요하다**

  - 이 랩은 오케스트레이터가 검색 에이전트 3종(local_db·gmail·drive)을 호출하는 구조로,
    오염이 한 에이전트에서 들어와 전체 답변을 좌우한다
  - 장기 메모리를 두면 오염된 답변이 세션을 넘어 재인용될 수 있어, 공격의 지속성이
    단일 질의를 넘어선다

◦ **방어 논문은 많지만, 이 환경에서 실제로 작동하는지 검증된 바가 없었다**

  - 논문 수치는 각자의 공격·코퍼스·리트리버 기준이며, 밀집 검색기와 LLM 생성 오염문을
    쓰는 이 랩에서 재현된다는 보장이 없다
  - 따라서 "논문을 소개한다"가 아니라 **"구현해서 이 환경에서 잰다"**를 과제로 삼았다

◦ **에이전트 장기 메모리 구현 및 오염 전파 차단** *(upstream 병합 완료, PR #8)*

  - 세션별 JSONL 대화 메모리(`append`/`recall`/`clear`, 최대 500건), 회상된 turn은
    일반 패시지와 동일하게 컨텍스트에 진입
  - **신뢰 전파**: 근거 패시지가 모두 `trusted`일 때만 해당 turn을 `trusted`로 기록 →
    오염 상태에서 생성된 답변은 `untrusted`가 되어 defended 모드가 자동 배제
  - 세션 간 오염 회상을 막기 위해 `session_id` 기본값을 고유값으로 전환

◦ **검색 단계 방어 3종 구현 및 실측** *(RAGPart upstream 병합, PR #7)*

  - RAGPart·RAGMask(arXiv:2512.24268) 논문 그대로 구현 → **이 공격에 무효**.
    RAGMask는 오히려 ASR을 0.75 → 0.88로 상승시킴
  - 원인 규명: 두 방어 모두 문서를 하나씩 질의와만 비교하는데, 정제 후 오염문의 질의
    유사도(0.75)가 진짜 정답 문단(0.74~0.84)과 **동점**이라 구별 불가
  - 대안으로 **중복성 필터**를 자체 구현 — 검색 후보를 평균연결 군집화해 임계값을 넘는
    군집을 제거. 임계값 0.90은 추측이 아니라 관측된 두 값(정상 최대 0.8705,
    오염 최소 0.9382) 사이에서 결정

◦ **생성 단계 방어 3종 구현 및 실측**

  - RobustRAG(Xiang et al., SaTML 2026) **논문 원안**(키워드 집계, α=0.2·β=3) 구현 →
    단독으로 ASR 0.75 → 0.38
  - `isolation`(격리만) 및 `isolate_conflict`(격리 + 충돌 탐지, 자체 변형) 구현
  - **절제 실험으로 이득의 출처를 규명**: 필터 뒤 정답률이 격리만 0.75, 충돌 규칙을
    얹으면 0.62 → 이득은 전적으로 논문의 격리에서 오며 자체 변형은 오히려 감점.
    해당 주장을 철회하고 문서에 기록

◦ **방어 on/off 토글 및 재현 가능한 측정 체계 구축**

  - 3단계 스위치: 요청 단위 필드 → 배포 기본값(`DEFAULT_*`) → 마스터 스위치
    (`DEFENSES_ENABLED=false`)로 전체 방어 일괄 차단
  - 측정 스크립트 2종(`measure_defenses.py`, `measure_clean_cost.py`)으로 공격 하 비교와
    **무공격 오탐 비용**을 모두 레포에서 재현
  - ASR과 정답률을 **분리 측정** — 기권으로 ASR만 내려가는 경우를 구별하기 위함

**※ 방어 배치 구조**

```
  질의
   │
   ▼
 ┌──────────────── 검색 단계 ────────────────┐
 │  RAGPart · RAGMask  →  무효               │
 │  중복성 필터        →  ASR 0.75 → 0.00    │   ← 지배적
 └───────────────────────────────────────────┘
   │  (오염문 제거된 패시지)
   ▼
 ┌──────────────── 생성 단계 ────────────────┐
 │  RobustRAG(논문)    →  ASR 0.75 → 0.38    │
 │  isolation          →  정답률 0.50 → 0.75 │   ← 권장
 │  isolate_conflict   →  0.75 → 0.62 (감점) │
 └───────────────────────────────────────────┘
   │
   ▼  답변
```

| 없음 | 없음 | 0.75 | 0.00 | 8/8 | 0/8 |

◦ **방어 도입 시 근거 있는 선택이 가능해진다**

  - "어떤 방어를 켤 것인가"에 대해 이 환경 기준의 실측치(효과·비용·오탐률)를 제시.
    권장 구성은 **중복성 필터(검색) + isolation(생성)**이며, 근거는 위 표에 있다
  - 임계값·파라미터가 측정에서 유도되어, 임베딩 모델이나 코퍼스가 바뀌어도 같은 절차로
    재산출할 수 있다

◦ **부정 결과가 후속 연구의 탐색 범위를 줄인다**

  - 재현 가능한 부정 결과 4건 확보 — RAGPart 무효, RAGMask 역효과, 자체 변형의 단독
    역효과, 절제 실험으로 밝힌 자체 변형의 기여 없음
  - "문서를 하나씩 질의와만 비교하는 계열은 이 공격에 원리적으로 약하다"는 결론은
    유사 방어의 사전 배제 근거가 된다

◦ **방어가 원리적으로 닿지 않는 구간이 특정되어 다음 과제가 명확해진다**

  - 오염문이 1개면 군집이 형성되지 않아 중복성 필터가 완전히 무력하며, 그 구간의 공격
    성공률은 이 랩 실측 60%·논문 NQ 기준 약 0.70으로 결코 약하지 않다
  - 따라서 다음 과제는 **단일 오염문 구간**과 **에이전트 실행 격리**(IsolateGPT,
    NDSS 2025)이며, 미측정 축인 AgentPoison(메모리 백도어)이 에이전트 보안의 나머지
    절반을 이룬다

◦ **측정 방법론 자체가 재사용 가능한 자산으로 남는다**

  - 방어를 껐다 켜는 3단계 스위치와 측정 스크립트가 레포에 포함되어, 새 방어를
    추가할 때 동일 조건 비교가 즉시 가능
  - 측정 과정에서 발견한 함정(임베딩 백엔드 기본값이 테스트용 해시로 조용히 대체되어
    결과 전체가 무의미해지는 문제)을 로그·가드로 차단해 재발을 방지
